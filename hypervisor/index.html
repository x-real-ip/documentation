    Install Proxmox

    These steps (re)install one node or the whole cluster. Everything the Proxmox API can configure is managed by OpenTofu in the infrastructure repository. The steps below are the manual work before and after tofu apply.

    1. Installer

    Use the graphical installer and enter the following values.

    Setting Value
    Target disk Force MP500 (112 GB NVMe)
    Filesystem ext4
    Advanced LVM options swapsize = 8, maxvz = 0
    Hostname (FQDN) pve-a.lan.stamx.nl
    Management interface Onboard NIC
    Pin interface names Enabled (nic0, nic1, nic2)
    IP address (CIDR) 10.0.99.2/24
    Gateway 10.0.99.1
    DNS server 10.0.99.1
    Setting Value
    Target disk KINGSTON SUV400S37240G (240 GB SATA)
    Filesystem ext4
    Advanced LVM options swapsize = 8, maxvz = 0
    Hostname (FQDN) pve-b.lan.stamx.nl
    Management interface Onboard NIC
    Pin interface names Enabled (nic0, nic1, nic2)
    IP address (CIDR) 10.0.99.3/24
    Gateway 10.0.99.1
    DNS server 10.0.99.1

    Warning

    Only select the boot disk. The other NVMe holds the vm-storage ZFS pool with the VM disks and must not be touched by the installer.

    Note

    maxvz = 0 skips the data volume, so there is no local-lvm storage to remove afterwards. VM disks live on vm-storage.

    Note

    The OpenTofu stack expects the interface names nic0 (onboard), nic1 and nic2 (PCI card). If the installer does not offer interface pinning, run pve-network-interface-pinning generate after the installation and reboot.

    2. Prepare each node

    1. Add the Ansible SSH key. Run this from the desktop.

      ssh-copy-id -i ~/.ssh/ansible.pub root@10.0.99.2

    2. Extend the root logical volume over the free space. The installer caps root at 96 GiB and leaves some space unallocated.

      lvextend -r -l +100%FREE pve/root

    3. Import the existing ZFS pool. Never create it, it holds the VM disks.

      zpool import -f vm-storage

    3. Create the cluster

    1. Create the cluster on pve-a.

      pvecm create pve-cluster

    2. Join pve-b. This asks for the root password of pve-a.

      pvecm add 10.0.99.2

    Reinstalling a single node

    The remaining node still knows the reinstalled node. Remove it there before joining, for example for pve-b:

    pvecm delnode pve-b
rm -r /etc/pve/nodes/pve-b

    4. Create the OpenTofu API token

    Run this once on any cluster node, for example over SSH from the desktop, and store tofu@pve!provider=<value> in Bitwarden. The value is shown only once.

    ssh root@10.0.99.2 'pveum user add tofu@pve --comment "OpenTofu" \
  && pveum aclmod / -user tofu@pve -role Administrator \
  && pveum user token add tofu@pve provider --privsep 0'

    Note

    Users, ACLs and tokens live in /etc/pve, which is replicated to every node in the cluster, so running this once is enough. Do it after creating the cluster: a joining node replaces its /etc/pve with the one from the cluster.

    5. Create the node certificates

    The web interface and API of every node use a certificate from the stamx CA. Skip this step when ~/certs/proxmox on the desktop already holds valid certificates.

    Run this on the desktop, not on a node

    The CA private key must never leave the desktop. OpenTofu reads the certificates from ~/certs/proxmox and uploads them to the nodes in the next step.

    1. Create the directory and go into it.

      mkdir -p ~/certs/proxmox && cd ~/certs/proxmox

    2. Copy the CA certificate from the ansible repository.

      cp ~/git-repositories/infrastructure/ansible/roles/ca_trust/files/stamx-ca-certificate.crt ca.crt

    3. Create a private key and a certificate request for every node.

      openssl req -new -newkey rsa:4096 -nodes -keyout pve-a.key -out pve-a.csr \
  -subj "/O=stamx/CN=pve-a.lan.stamx.nl" \
  -addext "subjectAltName=DNS:pve-a.lan.stamx.nl,DNS:pve-a,IP:10.0.99.2" \
  -addext "basicConstraints=CA:FALSE" \
  -addext "keyUsage=critical,digitalSignature,keyEncipherment" \
  -addext "extendedKeyUsage=serverAuth"

      openssl req -new -newkey rsa:4096 -nodes -keyout pve-b.key -out pve-b.csr \
  -subj "/O=stamx/CN=pve-b.lan.stamx.nl" \
  -addext "subjectAltName=DNS:pve-b.lan.stamx.nl,DNS:pve-b,IP:10.0.99.3" \
  -addext "basicConstraints=CA:FALSE" \
  -addext "keyUsage=critical,digitalSignature,keyEncipherment" \
  -addext "extendedKeyUsage=serverAuth"

    4. Sign the requests with the CA. Replace /path/to/stamx-ca-private.key with the location of the CA private key.

      openssl x509 -req -in pve-a.csr -CA ca.crt -CAkey /path/to/stamx-ca-private.key \
  -CAcreateserial -copy_extensions copyall -days 825 -sha256 -out pve-a.crt

      openssl x509 -req -in pve-b.csr -CA ca.crt -CAkey /path/to/stamx-ca-private.key \
  -CAcreateserial -copy_extensions copyall -days 825 -sha256 -out pve-b.crt

    5. Check the certificates. Both must report OK.

      openssl verify -CAfile ca.crt pve-a.crt pve-b.crt

    6. Remove the requests and protect the private keys.

      rm pve-a.csr pve-b.csr && chmod 600 pve-a.key pve-b.key

    Note

    The certificates are valid for 825 days. To renew them, repeat this step and run tofu apply.

    6. Apply OpenTofu

    Apply the proxmox stack, see OpenTofu usage.

    This configures the APT repositories (enterprise off, no-subscription on), DNS, /etc/hosts, the time zone, the bridges vmbr1 (wan) and vmbr2 (lan), the SDN VLANs, the vm-storage storage, the lsi-hba PCI mapping, the pools, the node certificates and the cluster options. The installer only creates vmbr0.

    The state in git still knows the resources from before the reinstall, so OpenTofu only creates what is missing.

    Reinstalling the whole cluster

    HA, storage replication and pool membership refer to guests. After a reinstall of both nodes those guests do not exist yet, so leave them out of the first apply:

    tofu apply \
  -exclude=proxmox_haresource.opnsense \
  -exclude=proxmox_replication.guest \
  -exclude=proxmox_pool_membership.guest

    Run a plain tofu apply once the guests are back. Reinstalling a single node does not need this, because the guests keep running on the other node.

    7. Finish each node

    1. Update the system. This needs the no-subscription repository from the previous step.

      apt update && apt dist-upgrade -y

    2. Enable Wake-on-LAN on the onboard NIC. Add the up line to the nic0 stanza in /etc/network/interfaces.

      auto nic0
iface nic0 inet manual
    up /sbin/ethtool -s nic0 wol g

    3. Run the 'Proxmox VE CPU Scaling Governor' script and set it to powersave.

    4. Add the QDevice.

    5. Set up two-factor authentication for root via Datacenter -> Permissions -> Two Factor.

    High Availability

    Add QDevice

    On the Qdevice

    1. This command sets the root password, enables root login in the SSH configuration, and restarts the SSH service.

      passwd root && sed -i 's/#PermitRootLogin/PermitRootLogin yes/' /etc/ssh/sshd_config && systemctl restart sshd

    2. Install corosync packages

      apt install corosync-qnetd corosync-qdevice

    On the Proxmox node(s)

    1. Install corosync-qdevice packages. Repeat for each node in your cluster.

      apt update && apt install corosync-qdevice -y

    2. Check current status

    Make a VM HA

    HA and storage replication are managed by OpenTofu in opentofu/stacks/proxmox/ha.tf. Changes made in the web interface are not in the code and get lost on a reinstall.

    1. Add the guest to replicated_guests in locals.tf, so its disks are replicated to pve-b every 15 minutes.
    2. Add a proxmox_haresource for the guest to ha.tf, and add it to the resources of a HA rule if it should prefer a node.
    3. Apply OpenTofu.

    Mount USB stick (backups)

    1. Find the USB stick device 

      lsblk

    2. Create mount directory 

      mkdir -p /mnt/pve/backup_usb-stick

    3. Mount (change <sd?> to the correct device) 

      mount /dev/<sd?> /mnt/pve/backup_usb-stick
